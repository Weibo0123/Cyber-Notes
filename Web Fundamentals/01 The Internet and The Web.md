# The Internet & The Web

## The Internet — A Network of Networks

The Internet connects computers worldwide so systems can communicate even when not directly connected. It's organized in layers (TCP/IP model):

| Layer | Responsibility | Examples |
|---|---|---|
| Link | Communication between directly-connected nodes | Ethernet, Wi-Fi |
| Internet | Routing data to the destination **machine** | IP |
| Transport | Delivering data to the destination **program**, via ports | TCP, UDP |
| Application | Application-level meaning of the data | HTTP, FTP, SMTP, SSH |

```
Link          → neighboring machine
Internet      → destination machine
Transport     → destination program
Application   → application-level meaning
```

## The World Wide Web

The **Web** is an information system built *on top of* the Internet — the Internet is the network infrastructure; the Web is the system of linked resources accessed over it (HTTP, HTML, hyperlinks).

```
Client / Browser --HTTP Request--> Web Server --HTTP Response--> Client / Browser
```
The browser turns user actions into HTTP requests; the server processes them and returns resources or dynamically generated responses.

Tim Berners-Lee proposed the Web at CERN in 1989; the first website launched in 1991.

## Static vs. Dynamic Resources

| | Static | Dynamic |
|---|---|---|
| What it is | Already exists in fixed form | Generated by server logic at request time |
| Example | `/cat.gif` | Content that depends on data, user input, time, etc. |

⚠️ A URL does **not** necessarily correspond to an actual file on disk — even `/cat.gif`-looking paths can be dynamically generated.

## Websites vs. Web Applications

| | Website (Web 1.0) | Web Application (Web 2.0) |
|---|---|---|
| Content | Mostly static | Dynamic, interactive |
| Changes | Same content to everyone; editing requires server-side changes | Changes per user input/state/stored data |
| Functionality | Limited | Auth, editing, search, transactions, etc. |

A **web application** is an interactive application that runs through a browser, typically with a client-side front end (HTML/CSS/JS), a server-side back end (application logic, auth, databases), and a database. Examples: webmail, online stores, web-based document editors.

## Web Apps vs. Native Apps

| | Web Application | Native Application |
|---|---|---|
| Runs | Inside a browser | Installed for a specific OS |
| Platform independence | High | Low — built per-platform |
| Installation | Usually none needed | Required |
| Updates | Centralized on the server, everyone gets the latest version immediately | Distributed/updated per device |
| OS/hardware access | Limited | Deeper integration, often better performance |

**Hybrid apps** and **Progressive Web Apps (PWAs)** blend both — web technologies wrapped with some native capability.

## Distribution Models

| | Open Source | Closed Source / Proprietary |
|---|---|---|
| Source code | Publicly available, customizable | Controlled by the vendor |
| Examples | WordPress, OpenCart, Joomla | Wix, Shopify, DotNetNuke |

## Cheat Sheet

```
TCP/IP layers:  Link → Internet → Transport → Application
Web = information system (HTTP/HTML/links) built ON TOP OF the Internet

Static resource   → fixed, pre-existing content
Dynamic resource   → generated per-request; URL ≠ necessarily a real file

Website (1.0)        → mostly static, same for everyone
Web Application (2.0)  → dynamic, interactive, stateful features

Web App    → browser-based, centrally updated, platform-independent
Native App  → installed, deeper OS access, per-platform builds

Open source → code public/customizable   Closed source → vendor-controlled
```
